## 3. 机器与工具链

- 所有工具解析到 `<工具链目录>`（**用户级** PATH；Machine 级不含它们）。**环境变量在进程启动时快照**，新开的终端才认得新值。
- 跑仪器时 PATH 上必须解析到这一份：`pnpm test` 会 spawn `node`。**独立链已验证（2026-10-16）**：PATH 换成系统目录 + 用户目录（不含 `.dsh`）后，`pnpm install --frozen-lockfile`（lockfile 零改动）、`pnpm typecheck`、`pnpm test` 全绿。
- PowerShell 执行策略：`CurrentUser = RemoteSigned`。Windows 默认 `Restricted`，Node 的 `.ps1` 入口会被拒；`cmd` 的 `.cmd` 入口一直是好的。
- **DSH 自带的 Node 是另一份**：`%USERPROFILE%\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node`（`v24.21.0`），被裁过（只有 `bin/`、`node_modules/`、`LICENSE`，**没有 npm / npx / corepack**）。**不要改它、不要往里装东西**——那是平台管理的目录。自带 pnpm 也在同一目录下（`11.7.0`），**不在 PATH 上**，别用它发布或跑仪器。
- **Node 钉在 24.18.0 的理由**：与部署环境的 Node 同版本，升级要**两边一起动**。24.18.1 是安全发布版（修 12 条 CVE，含若干 High），但当时决定先对齐部署版本。**AI 不要自行升级 Node / pnpm；这是环境变更，由人发起。**

## 5. 开发回路与判据

**回路（只有一条）**：

```text
pnpm build → 完全退出并重开 DSH → 在 GUI 里验收
```

- 客户端半边（`lib/client.js`）原则上会热生效，但**不写成步骤、也不当判据**；Host 半边（`lib/index.js`）本来就必须重启。统一成一条路，避免在"要不要等 HMR / 要不要刷新"上误判。
- **桌面端没有刷新按钮**：不要写"刷新页面 / Ctrl+Shift+R"；要重来就**重启 DSH**。
- **GUI 验收只有人能确认**。AI 能跑 build / typecheck / test、能读产物，但不能替人宣称"在界面里验过"。交付话术是"待你在 GUI 确认"。

**判据**：

| 命令 | 管什么 | 何时必须跑 |
|---|---|---|
| `pnpm typecheck` | 三份 `tsc --noEmit`：客户端 / Host / `scripts/`（探针） | 改了 `src/`、`scripts/`、`tsconfig*` |
| `pnpm test` | 块级保存验收（`scripts/probe-block.ts`）：零编辑逐字节、改一个字只那段变、整篇标准写、末尾插块、表格改一格 | 改了代码或发布物；**发版前** |
| `pnpm verify:map` | 文件职责与仓库里的代码文件是否对得上（缺行 / 死链 / 历史词） | 新增或删除文件后；发版前 |
| `pnpm probe:block` | 单台块级仪器（与 `pnpm test` 同一支） | 只动读写层时 |
| `node scripts/probe-vault.mjs <baseUrl>` | 真实 HTTP 面（要 DSH 在跑） | 动 Host 路由时；**会改授权根**，别在正用的 DSH 上跑 |

- **数量以命令输出为准**，本文不抄用例条数（会变）。
- `probe-vault` 缺省打 `http://127.0.0.1:19387`，**不一定是正在跑的那个 GUI**；跑之前把当前地址传进去。
- **最近一次全绿**：2026-10-18，`pnpm typecheck` ＋ `pnpm test` 均 exit 0（在 DSH `0.2.1-rc.2` 上）。
