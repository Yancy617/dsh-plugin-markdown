## 1. 一句话

**原文是文档，模型只是它的视图。**
用户每改一次，编辑器把改动落到原文的某个位置上；保存就是把这份原文写回磁盘。全程没有搜索、没有“找不到”，所以保存不会因为“定位”失败。

## 2. 状态模型

| 名字 | 是什么 | 谁用 |
|---|---|---|
| **`saved`** | 磁盘上的原文（打开时、保存成功后） | 源码视图、保存比较、冲突判断 |
| **`source`** | 当前原文镜像（随每一次编辑同步更新） | 保存写盘、行号以外的一切落盘内容 |
| **`model`** | 编辑器树（Lexical） | 富文本、光标、撤销、目录、字数 |
| **`content`** | 模型导出的 Markdown | 只用于搜索/字数/历史等 UI 派生，**不再用于落盘** |

- `dirty = source !== saved`。
- 保存：`writeText(source)`；成功后 `saved = source`。
- 不编辑：`source === saved`，不写盘。
- 撤销到底：`source` 回到 `saved`，不写盘。
- 打开/重新载入：`source = saved = 磁盘文本`，再按它建模型。
- 新建：`source = saved = ''`，后续同一套流程。

**源码视图显示 `saved`**（磁盘文件），不显示未保存的 `source`。这是已确认的产品口径；页面别处可以用角标提示“有未保存改动”。

## 3. 源位置（Source Map）

### 3.1 每个可编辑单元记什么

| 单元 | 记什么 |
|---|---|
| 块（段落、标题、列表、引用、代码块、表格、分割线…） | 在 `source` 里的 `[start, end)` |
| 行内节点（文字、链接、图片、行内代码、强调…） | 自己的 `[start, end)` |
| 文字节点 | `[start, end)` ＋ **字符映射**：可见第 i 个字 → 原文第几个字节（转义 `\*`、实体 `&copy;`、代码段内侧空格都要能对上） |
| 可编辑字段（标题级别、列表记号/缩进、任务框、链接目标/标题、图片 alt/目标/标题、表格单元格/对齐） | 字段自己的 `[start, end)` |

**通用来源**：mdast 的 `position` 已经给到每个块/行内节点；导入时统一挂到 Lexical 节点上。**字段级**位置由各模块在自己的读手里细化（例如标题的 `#`、列表的记号、表格的竖线、代码围栏）。

### 3.2 位置的稳定性

编辑会让后面的位置整体平移。不做“每次改都遍历所有节点改数字”，而是：

- 节点上记 **锚点**（一个稳定的 id ＋ 段内偏移）；
- 一份 **增量索引**（Fenwick/区间树）记录每次编辑产生的偏移变化；
- 保存时把锚点解析成当前 `source` 的绝对位置。

这样每次编辑只更新索引和受影响的一小段，不碰全树。

### 3.3 粒度原则

**能小则小**：用户改一个字，替换的就是那个字；不替换整段、整行、整块。只有“编辑本身改变了这个构造”时才扩大到父节点：

- 改标题文字 → 只换文字；`#` 和收尾 `##` 不动；
- 改标题级别 → 换级别那一段（模块提供字段位置）；
- 加粗一个词 → 在词的两端插 `**`（父节点是新的，用子节点位置的并集）；
- 改链接目标 → 只换目标那一段；
- 改表格一格 → 只换那一格；
- 加一行 → 插在行边界，不动别的行；
- 加一列 → 每行在列边界插一格（不动别的格）；
- 改代码内容 → 先换内容；如果内容里出现反引号导致围栏要变，才换成整个代码段；
- 删整项/整块 → 删它的 `[start, end)`。

## 4. 编辑同步（Source Sync）

### 4.1 每次编辑器更新

比较“上一版树”和“这一版树”（Lexical 的 `prevEditorState` ＋ `dirtyLeaves`/`dirtyElements`，只看脏子树）：

1. 找**最小的变化节点**（文字变了、格式变了、子节点增删、类型变了）。
2. 按 §3 的粒度，把它映射成 `source` 上的一次编辑：`{start, end, newText}`。
3. 把这次编辑应用到 `source`，同时更新增量索引与受影响节点的锚点。
4. 新节点没有原文位置：插入点由前一个/后一个兄弟的位置决定；没有兄弟时用父节点的边界。

### 4.2 操作 → 源编辑

| 操作 | 源上的动作 |
|---|---|
| 输入/删除文字 | 换文字节点里那一段（字符映射负责转义/实体） |
| 回车（拆段） | 在光标对应的原文位置插入段落分隔（EOL 按文件）；两半各自保留自己的位置 |
| 退格（并段） | 删除两段之间的分隔；合并后的文字替换两段文字的范围 |
| 加粗/斜体/删除线 | 在文字范围两端插入/删除标记；标记写法按标准 |
| 改标题级别 | 换级别字段 |
| 列表缩进/反缩进 | 把这一项的原文范围“删掉再插到新缩进处”，只动这一项的行 |
| 增删列表项 | 在项边界插入/删除整项 |
| 表格改格 | 换单元格文字 |
| 表格增删行 | 在行边界插入/删除整行 |
| 表格增删列 | 每行在列边界插入/删除一格；分隔行同步 |
| 表格对齐 | 只换分隔行那一格（沿用现有做法） |
| 改链接/图片字段 | 换目标/标题/alt 那一段 |
| 粘贴 | 在光标位置插入新内容（写手出标准形式）；不碰原有字节 |
| 剪切 | 删除选区的原文范围 |
| 撤销/重做 | 树回到某状态 → 同步自然算出反向编辑；不依赖日志 |
| 全部替换 | 每个命中位置各产生一次编辑；逐个应用 |
| 文件改名/移动（图片改址） | 只换图片目标那几段 |
| 重新载入 | 丢弃 `source`，重读磁盘 |

### 4.3 新内容的写法（写手）

新节点/新文字没有原文，必须由写手生成**标准 ＋ 上下文兼容**的 Markdown：

- 纯文字：转义 `[` `]` `<` `!`、行首的 `#` `-` `1.` `>` `---` 等；
- 列表新项：沿用列表的记号/缩进/松紧；
- 表格新行/新格：沿用表格的外框、分隔行、竖线风格；
- 引用新行：沿用 `>` 的空格风格；
- 代码：围栏长度/字符/信息串按标准；
- 图片目标含空格：写成 `<...>`；
- 行尾：新行沿用文件的 EOL（CRLF 文件用 `\r\n`；新建文档用 LF）。

### 4.4 失败怎么办

同步对不上（位置缺失、范围重叠、字符映射断裂）是 **bug**，不是用户要处理的状态：

- 开发期：断言，测试零容忍；
- 线上：**不静默改文件**；提示“这一处没能写入原文，请撤销这一步”，保留模型，不写盘；
- 任何情况下不退回“整篇重写”。

### 4.5 自检

每次保存前（开发期/测试里）用 `source` 重新导入一遍，和当前树做**语义**比较：结构一致才算同步正确。生产环境可采样或在调试开关下开启。

## 5. 保存与流程

| 场景 | 行为 |
|---|---|
| 打开 | 读磁盘 → `saved = source = 文本` → 建模型；源码视图显示 `saved` |
| 编辑 | 每次更新同步 `source`；`dirty = source !== saved` |
| 自动保存 | `dirty` 时按现有节奏写 `source` |
| 手动保存 | 同一路径；`source === saved` 时不写 |
| 写入期间继续编辑 | 写的是**发送时的 `source` 快照**；成功后 `saved = 快照`；期间的新改动仍是 dirty，下一次再写 |
| 关闭标签 | 默认保存 `source` 后关闭；失败才弹窗（沿用现有协议） |
| 切换标签/视图 | 不写盘；`source` 留在内存 |
| 重新载入 | 重读磁盘，重置 `source`/`saved`/模型 |
| 新建 | `source = saved = ''`；第一次输入从位置 0 开始 |
| 只读示例 | 不写 |
| 外部修改（stale） | 沿用 CAS ＋ 分类；`same-as-target` / `same-as-saved` / `different` 的判定以 `saved` 与 `source` 为准 |
| 文件改名/移动 | 图片改址作为一次源编辑（只换目标），其余字节不动 |
| 大文档 | 只同步脏子树；源码视图按需虚拟化；保存仍是写 `source` |

**注意**：`content`（模型导出）不再参与落盘；`baseline` 不再用于“是否要写”。`savePlan` 可以简化为 `source !== saved`，`staleWrite` 继续用 `saved`。

## 6. 源码模式

- **只读**：不能编辑、没有光标、没有原生撤销、没有拼写检查；
- **永远显示磁盘文件** `saved`；未保存的 `source` 不在这里显示；
- **不显示文档目录**；布局里不出现目录列；
- 左侧**行号**；不另设行数条——工具栏已经写着「字符 · 词 · 行」；
- 行号规则：从 1 开始，按 `\n` 切分；文末换行产生的空行也编号；空文件显示 1 行（空白行）；
- 不做语法高亮（除非另定）；
- 大文件：行数很多时用虚拟滚动；行号与行数只读 `saved`，不解析 Markdown。

## 7. 新内容合规（第 2 条不变量）

新写出来的每一段，必须：

1. **是标准 Markdown**：CommonMark 0.31.2 ＋ GFM（表格/任务项/删除线/裸自动链接）；
2. **在上下文里解析成同一个结构**：插进 `*` 列表的新项不能写成 `-`；插进无外框表的新行要能被同一张表接受；引用新行、嵌套列表、任务框同理；
3. **不出现私有写法**：`%%dsh-`、U+2060、U+0000 等哨兵不许落盘；
4. **原文里的非标准写法**（历史文件）不因为一次编辑被强行标准化——它们不在新内容里。

**验收**：新建文档矩阵（每种可造节点 → 导出 → 参考解析器 → 结构与编辑器一致）；修改文档时，对“被编辑的那一块”做同样检查。

这些构造在模型里就丢了结构，用户看不见/编辑不了；必须补：

| BOM / CRLF | 前缀/行尾；不触碰；新行沿用 | sourceSync |

### 9.3 操作与流程

| 场景 | 行为 |
|---|---|
| 新建空文档 | `source=''`；第一次输入从 0 插入；写手按标准 |
| 打开已有文档 | 读 → `saved/source` → 建模型 |
| 编辑后保存 | 写 `source` |
| 自动保存 | `dirty` 才写 |
| 关闭标签 | 保存后关闭 |
| 切换标签/视图 | 不写；内存保留 |
| 撤销/重做 | 树变化 → 反向同步 |
| 全部替换 | 多个位置各一次编辑 |
| 粘贴 / 剪切 | 插入/删除；不碰旧字节 |
| 重新载入 | 重读磁盘 |
| 外部修改 | CAS 分类 |
| 文件改名/移动 | 图片改址只换目标 |
| 插入图片 | 新节点；目标标准 |
| 只读示例 | 不写 |
| 大文档 | 脏子树同步；源码视图虚拟化 |
| 源码视图 | 只读、无目录、行号＋总行数、显示 `saved` |
| 搜索/目录/字数 | 只读派生，不写 |
| 粘贴截图 / 图片文件 | 落 `.img/` ＋ 插入图片节点（新内容，标准目标） |
| 块转换（段落↔标题/引用/列表，斜杠菜单/工具栏） | 按目标块的字段/结构编辑，只动这一块 |
| 有序列表新项 | 序号按列表规则；不重排已有项 |
| 空列表项 / 空标题 | 按标准写；不吞 |
| 输入法组合（IME） | 组合期不落盘；提交后同步一次 |
| 文件被删除 / 授权撤销 | 停止写入（沿用 `dropped` / 只读判定） |
| 参差表 / 合并格 / 非矩形表 | 结构编辑拒绝；文字编辑仍按格 |

## 10. 仪器与验收

### 10.1 新增仪器

| 仪器 | 做什么 |
|---|---|
| `probe-save`（新） | 打开 → 编辑 → 保存路径；逐场景断言“改动范围外逐字节等于原文” |
| `probe-fuzz`（新） | 真实文档随机位置插入/删除/替换 N 次；保存必须成功；未触碰字节不变；重新导入与树同构 |
| `probe-newdoc`（新） | 新建文档矩阵：每种节点造一遍 → 导出 → 参考解析器 → 结构一致；无哨兵 |
| `probe-sourceview`（新） | 源码视图文本 === `saved`；行号/总行数正确；只读；无目录 |
| 现有 `probe:audit` / `probe:survey` | 保留为回归语料；新增“保存路径”列，不再拿裸导出当铁律判据 |
| 现有 `probe:units` | 增加 sourceMap / 字符映射 / 同步规则的单测 |

### 10.2 验收判据

1. 不编辑 → 不写盘，逐字节不变。
2. 加一字 → 删一字 → 保存，逐字节不变（中途保存也一样）。
3. 只追加一行 → 差异只有这一行及其必需换行。
4. 源码视图 === 磁盘文件（只读、行号、总行数）。
5. 改动范围外逐字节不变（每个场景）。
6. 随机编辑 fuzz：0 次同步失败、0 次范围外改动、0 次结构不一致。
7. 新建文档：参考解析器结构与编辑器一致；0 哨兵。
8. 撤销到底：文件 === 原文。
9. `pnpm test` 红/绿与铁律一致：旧的 `byte-change`、`known-gap` 必须翻红后修绿。

## 13. 风险与边界

1. **Lexical 的节点拆分/合并**：回车、退格、粘贴会产生新 key；sourceSync 必须按“前后两版树”处理，不能按 key 假设。
2. **编码改写过的正文**：`encodeBodyForImport` 会在 mdast 之前插哨兵 / 改字符（多空行、raw block、引用式链接、字符引用），mdast 位置是**编码后**正文的偏移。现在块级位置由**再解析原文**补齐（`$attachOriginalBlockRanges`）；**行内位置仍不可用**，这类文档走块级替换。块数对不上时回退整篇导出。行内位置的编码→原文映射是后续细化项。
3. **性能**：每次击键只同步脏子树；位置用锚点＋增量索引；4MB 文档要实测导入/保存/击键耗时。
3. **源码只读**：没有 raw 编辑退路，读侧 P0 必须补全，否则那些构造不可编辑。
4. **表格列编辑**：每行插一格，要保持未动格子的字节；边界情况（无外框、参差行、合并格）单独测。
5. **代码围栏**：内容里出现反引号时，可能整段换围栏；这是“编辑本身要求”的范围。
6. **自检成本**：保存前重新导入做语义比较，大文档可能慢；可采样/调试开关。
7. **BOM / 混合行尾**：平台 `readText` 是否保留 BOM 未验；混合行尾的新行 EOL 取最近的。
8. **非 UTF-8**：平台拒绝；错误文案待真机确认。
9. **外部修改**：沿用 CAS；`saved` 是判据。
10. **不同步 = bug**：任何“对不上”都不允许变成“整篇重写”。

## 14. 不做

- 不做非 UTF-8 的编码转换；
- 不做“保存时文本 diff / 搜索 oldString”；
- 不做“失败时整篇重写”；
- 不做源码模式编辑；
- 不做源码模式目录；
- 不做语法高亮（除非另定）；
- 不改文件树/网页/搜索等与保真无关的功能。
