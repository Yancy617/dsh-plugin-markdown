## 1. 两个半边

| 半边 | 运行在 | 入口 | 职责 | 边界 |
|---|---|---|---|---|

- 文件读写走 `ctx.fs`；改名 / 删除 / 建目录 / 移动走 `node:fs`（`ctx.fs` 没有这些动词）。
- 路由契约在 `src/shared/protocol.ts`；客户端运输在 `src/client/request.ts` 与 `src/client/vaultClient.ts`。

## 4. 主要数据流

**打开文档**：`GET read` → `host/vault.ts` 的 `read` → `importDocumentMarkdown`（mdast 解析原始正文 → `mdastLower` 映射 → `projectDocumentNodes` 逐块判 rich / source → `$ensureTrailingParagraph`）→ 编辑器根节点，同时返回块级保存基线（每个顶层块的原文 span + 标准写法）。rich 按语义渲染；source 是**可编辑的普通文本**（Markdown 源，textarea），不是只读。

**保存**：编辑提交 → `$saveBody`：未改的顶层块从原文切片（块间空行一起搬），改过 / 新块由 `mdastLift` 标准写；source 块原样写回（用户自己写的 Markdown），相邻同类列表换标记；写手抛错退回纯文本段落 → 缓冲区的 `source` → `POST write`（CAS + `version`）→ 回写 `saved`；`stale-version` 先重读分类（已是目标 / 仅元数据 / 真冲突），只有真冲突才拒绝，并弹二选一（保留我的 / 用磁盘的）。

**编辑提交**：`onChange` 把编辑器这一次产出的正文交给工作台；工作台把它同时记进 `content`（显示 / 字数 / 目录 / 重挂时的重导入）与 `source`（保存对象）。两处写在同一个函数里，所以不会各说一套。`planSaveSource` 用 `source !== saved` 判定该不该写。source 块的 textarea 改动带 `SOURCE_EDIT_TAG`，`EditorBridge` 据此整篇重算，不会复用旧 `written`。

**撤销**：`documentSessions.ts` 按路径持有每篇的 `HistoryState` → `historySession.ts` 在编辑器挂载时把历史条目的编辑器引用改到本次编辑器、补上初始状态、按 100 步 / 1 秒合并注册 → 关闭 / 重新载入 `forget`，改名 / 移动 `repath`。

**关闭文档**：`requestClose` → 默认立即保存并关闭，保存期间冻结视图 → `closeTab` 写干净后 `forgetTabs` 销毁 buffer、标签与文档会话；失败才弹窗（重试 / 放弃更改并关闭 / 取消）；`Shift+关闭` 或命令面板可放弃更改。

**自动保存**：编辑 → `planSaveSource` 判定 → `autoSave.nextWriteDelay` → `MarkdownWorkbench.writeActive` → `POST write`。

**面板快照**：任何状态变化 → `useWorkbenchSnapshot` 写穿 `WorkbenchStore`；滚动只改快照、不触发渲染；面板卸载后落地的写结果直接补进快照；切回来按快照恢复缓冲区、标签、目录与滚动位置。

**文件树与移动**：`list` / `directories` → `treeOrder` / `treeDrop` → `POST move` / `rename` → `reloadLevels`。

**创建副本**：命令 `duplicate` → `duplicateEntry`（源文档有未保存修改就先 flush）→ `nextCopyName` 从该目录的完整条目里取第一个空号 → `POST copy`（Host 用 `copyFile` ＋ `COPYFILE_EXCL` 做字节复制）→ `placeCopy` 写 `tree.json` → 静默重读该层。副本不自动打开；排序写失败只给警告。

**复制 / 粘贴**：复制 → `clipboardMarkdown.ts` 的 `$selectionMarkdown`（完整块块级序列化，部分选择 HTML 读法）→ `text/plain`（Markdown）＋ `text/html` ＋ `application/x-dsh-markdown`，不写 Lexical JSON；粘贴 → `PasteMarkdownPlugin` **图片优先**，其次自有 Markdown，再次 HTML / 纯文本 → `$pastedMarkdownNodes`（mdastLower）。

**图片**：粘贴或选文件 → `imageInsert` 经 `AssetWriter` 端口命名并写入 → 工作台把端口实现为 `POST asset` → `imagePath` 拼相对地址 → `ImageNode`。

**链接与网页**：点击 → `linkClick.externalDestination` → `webPageRoute` → 平台浏览器标签（`dshtab`）或本面板网页标签（`panel`）；拿不到打开器时才退回系统浏览器。

**检查更新**：命令面板或齿轮菜单 → `fetchUpdateCheck` → `GET updateCheck` → `checkForUpdate` → npm registry。

## 5. 全局不变量

- **文档 Markdown 只有三扇门**：`importDocumentMarkdown` / `serializeDocumentMarkdown` / `$pastedMarkdownNodes`，都在 `documentMarkdown.ts`；保存另走 `blockSave.ts` 的 `$saveBody`。
- **一块内容只有一个定义**：`serializeBlock(liftBlock(node))`。基线（`saveBase.ts` 的 `BaseBlock.written`）存的就是它，“改没改”= 再算一次是否相同。新增节点或属性只改 lower / lift 各一支，没有第二份语义清单。
- **空段落只有一个定义**：`emptyParagraph.ts` 的 `$isEmptyParagraph`（没有子节点）。保存的块间空白、整篇标准写、复制、文末不变量都用它。
- **写盘只有一处**：`MarkdownWorkbench.tsx` 的 `writeActive(path)`；写的是缓冲区的 `source`。「保留我的」也走它，只多一个 `force` 参数（不要版本号）。
- **冲突永远交给人**：CAS 拒绝只在内容真的不同时成为冲突；面板弹二选一——「用磁盘的」按路径重载，「保留我的」先按副本规则在同一目录留一份磁盘版，再强制写。不自动合并、不自动覆盖。
- **整块面板有兜底**：`MarkdownPanel` 用 `ErrorBoundary` 包住工作台；卡片给原因、技术详情（`error.stack` ＋ React 组件栈，可复制）与「重新加载面板」。只接渲染期，挂载之后的事件 / effect 抛错不在其内。
- **版本检查只问 stat**：回面板时每个打开的文档只取版本（`GET stat`），不读正文；Host 没有该路由时退回 read。查询并行，一篇大文档不拖住其他标签的 ⟳；示例文档不参与（它们的正文是包内内存，不会被改）。
- **块级原文不动**：`saveBase.ts` 的 `BaseBlock` 记每个顶层块的 span + 标准写法（存在文档会话里，不在节点 state 上）；没改的块从原文切片，改过的块由 `mdastLift.ts` 标准写。基线还记着“这组 span 描述的是哪一份正文”，挂载时一次比较就能发现“正文被编辑器之外改写却没重挂”，发现就丢掉基线（下一次保存整篇标准重写，内容不丢）。
- **撤销历史属于打开文档的会话**：`documentSessions.ts` 按路径持有历史与保存基线；编辑器只是挂载 / 卸载它。关闭文档即丢，源码视图只读、不进入历史。
- **正文改写只有一个入口**：`MarkdownWorkbench.tsx` 的 `replaceText(path, 正文, reason)` —— 丢会话（撤销历史 + 保存基线）、改三份正文、重挂视图、丢弃在飞的写入，一次做完。重新载入与移动改址都走它，移动事务只负责算出新正文。基线自检（`isStaleBase`）是这条规则的兜底，不是它的替代。
- **读写只有一层映射**：`mdastLower.ts`（mdast → Lexical）与 `mdastLift.ts`（Lexical → mdast → 标准 GFM）；没有每种语法一套写手 / 正则。
- **新写的标准写法交给库**：`mdast-util-to-markdown` ＋ `mdast-util-gfm`；旧拼写只在“未改的块”里靠原文切片保住。
- **Host 拥有文件系统**：客户端只发 HTTP；`ctx.fs` 负责读写，`node:fs` 负责结构操作。
- **命名规则只有一份**：`shared/entryName.ts`；客户端只负责在输入时提示，Host 在写新文件 / 改名 / 建目录前用自己的平台再判一次。
- **副本是字节复制**：Host 用 `copyFile`，不经过 Markdown 解析 / 写回；副本与源文件同目录，图片相对地址因此不需要重写。
- **表格是“一个块”**：没动过就逐字节回放；任何编辑（一格文字、行列、对齐）都让整表按标准 GFM 重写，表格前后的其他块不动。
- **大文档不拒绝、不静默失败**：没有最大打开大小；≥4MB 先问一句，慢不慢由**实测导入耗时**说；导入抛错由 `EditorBoundary` 接住并给源码视图这条退路。任何打开 / 失败路径都不写盘。
- **代码块横幅画在编辑面之外**：`codeBlocks.ts` 出清单，`codeChrome.tsx` 在 `.md-root` 的兄弟层上按代码块的实测矩形画横幅与复制按钮；任何控件都不进 Lexical 的 DOM 子树。
- **协议只有一份**：`src/shared/protocol.ts`；客户端不另写路由形状。
- **版本偏斜是常态**：页面会热重载、Host 要重启；`state` 带 `PROTOCOL_VERSION`，客户端读到字段缺失（旧 Host）时提示一次重启，而不是靠逐条路由报错。请求体有 64 MiB 上限，超限答 413。
- **跨功能事务留在组合根**：换仓库 / 撤授权 / 路径跟随要同时动缓冲区、标签、树、会话与提示，它们的原子性由 `MarkdownWorkbench.tsx` 保证；自动保存节奏与关闭三态分别在 `useWriteScheduler.ts` / `useCloseProtocol.ts`，不反向依赖工作台。
